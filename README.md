# Одеський ліцей № 86

Повний застосунок на Next.js 16, TypeScript, Tailwind CSS 4, Motion, Lucide та Supabase. Усі тексти інтерфейсу — українською. Включає новини, оголошення, пошук, сторінки закладу, чат із попередньою модерацією та захищений кабінет адміністрації.

## Запуск

Потрібен Node.js 22.9+ та npm.

```powershell
cd "C:\Users\Administrator\Documents\Codex\2026-11-06\build-a-production-ready-news-website\outputs\lyceum86"
npm ci
npm run dev
```

Відкрийте адресу, яку виведе Next.js. Для виробничого режиму:

```powershell
npm run build
npm start
```

Залежності вже встановлено. `.env.local` містить надані параметри Supabase; файл ігнорується Git. У URL має бути тільки корінь проєкту (`https://…supabase.co`), без `/rest/v1/`. Серверний ключ `service_role` застосунку не потрібний.

## Підключення бази

1. Відкрийте SQL Editor вашого проєкту Supabase.
2. Виконайте **один раз** `supabase/setup.sql`. Це перевірена міграція та три реальні новини з посиланнями на першоджерела. Скрипт не видаляє наявні таблиці. Якщо однойменні таблиці вже існують, транзакція міграції зупиниться; не застосовуйте її повторно.
3. Для CLI-оточення натомість використовуйте `supabase/migrations/202611060001_initial.sql`, потім `supabase/seed.sql`. Не застосовуйте одночасно обидва способи.
4. У Supabase Auth → URL Configuration задайте адресу сайту і дозволені redirect URLs: `http://localhost:3000/auth/confirm`, `http://127.0.0.1:3000/auth/confirm` та відповідні адреси виробничого домену. Для відновлення дозволіть також `/auth/confirm?next=/auth/password`.
5. Увімкніть підтвердження електронної адреси; налаштуйте власний SMTP для виробничої доставки листів. Встановіть мінімальну довжину пароля 12 символів та обмеження частоти Auth-запитів у панелі Supabase.
6. Замініть шаблони підтвердження та відновлення листів в Auth → Email Templates файлами `supabase/email/confirmation.html` і `supabase/email/recovery.html`. Їхні посилання використовують `TokenHash`, тому підтвердження працює і з іншого пристрою.
7. Зареєструйте адміністратора через `/auth`, підтвердьте адресу, знайдіть його UUID у Supabase Auth → Users. У SQL Editor від імені власника бази (`postgres`) виконайте одноразове призначення, підставивши справжній UUID:

```sql
select public.bootstrap_first_admin('UUID_ПІДТВЕРДЖЕНОГО_КОРИСТУВАЧА'::uuid);
```

Функція вимагає наявного користувача з підтвердженою електронною адресою, блокує повторне призначення та одночасні спроби. Вона недоступна ролям `anon`, `authenticated` і `service_role`; виконується з правами довіреного власника, який її викликає. Перший зареєстрований користувач автоматично не отримує жодних привілеїв. Подальші зміни складу адміністраторів виконує власник бази через SQL Editor.

Право адміністратора зберігається в окремій захищеній таблиці. Його неможливо надати собі через реєстрацію чи метадані профілю. Усі зміни додатково перевіряються сервером і RLS у базі. `setup.sql` застосовує схему та початкові матеріали однією транзакцією; помилка не залишить частково встановленого застосунку.

## Функції

- Новини: справжні зображення, категорії, пошук тексту, чернетки, закріплення, строк показу, окремі сторінки, SEO та структуровані дані.
- Оголошення: окремий тип публікації, строк показу та закріплення.
- Кабінет: створення, редагування і видалення; захист від перезапису чужих одночасних правок; серверне завантаження JPEG/PNG/WebP до 5 МБ із перевіркою сигнатури файлу.
- Чат: лише після входу, оновлення через Supabase Realtime, повторне з’єднання й резервне опитування, історія, видалення власних повідомлень.
- Модерація: нові повідомлення приховано до схвалення; скарги, приховування та обмеження надсилання на 24 години з можливістю скасування.
- Захист: RLS, окремі права на стовпці, перевірка користувача, журнал змін публікацій і модерації, серверні заголовки безпеки, жодних серверних секретів у браузері.
- Протидія спаму: щонайменше 5 секунд між повідомленнями, до 30 на годину. Видалення повідомлення не скидає ліміт.
- Доступність: семантична розмітка, український `lang`, клавіатурна навігація, помітний фокус, підписи полів, зменшення анімацій за системними налаштуваннями.

Незареєстровані відвідувачі не читають чат. Редактор підтримує звичайний текст з абзацами; довільний HTML не виконується. Файли сховища доступні публічно, завантаження дозволене лише адміністраторам. Якщо прибрати фото з публікації, оригінал залишається у сховищі; непотрібні файли можна прибрати через Supabase Storage після перевірки посилань.

## Перевірки

```powershell
npm run typecheck
npm test
npm run test:database
npm run build
npm audit --omit=dev
```

Тести бази запускають справжній PostgreSQL у PGlite з локальними імітаціями службових схем Supabase. Вони перевіряють RLS під ролями `anon` та `authenticated`, захист від підвищення привілеїв, приватність чернеток і чату, модерацію, скарги, ліміти після видалення, блокування, сховище й аудит. Це не заміна інтеграційній перевірці Auth, Realtime і Storage у вашому проєкті після виконання міграції.

## Розгортання

Розгорніть каталог як Next.js застосунок на сумісному Node.js-хостингу або Vercel. Встановіть три змінні з `.env.example`, причому `NEXT_PUBLIC_SITE_URL` має бути фактичним HTTPS-доменом. Після зміни `NEXT_PUBLIC_*` потрібна нова збірка. Додайте домен у Supabase Auth, налаштуйте HTTPS, резервне копіювання бази та моніторинг помилок.

Sites у цьому середовищі надає Workers/Vinext-хостинг. Цей проєкт збережено на запитаному Next.js; його серверну збірку не можна опублікувати як статичний сайт без втрати функцій.

Перед публічним запуском виконайте наскрізний сценарій: реєстрація → підтвердження пошти → вхід → повідомлення → схвалення в іншій сесії → поява в чаті; додайте й відредагуйте публікацію із завантаженим зображенням; перевірте відновлення пароля та зняття блокування. Призначте відповідального оператора даних і погодьте фактичні строки зберігання та текст приватності. Призначення адміністратора й політика зберігання — операційні налаштування власника.

## Джерела

Перелік перевірених офіційних джерел і походження фотографій — у `SOURCES.md`. Початкові новини — короткі перекази, не вигадані події. Оголошень не вигадано. Без параметрів Supabase доступні перевірені початкові новини; після підключення база є єдиним джерелом публікацій. Якщо база недоступна, інтерфейс повідомляє про помилку.
